## ✅ Ce qui est fonctionnel

### 1. Analyse Lexicale (Flex) — `tpcas.l`
Tous les tokens TPC sont reconnus :
- Types : `int`, `char`, `void`, `struct`
- Mots-clés : `if`, `else`, `while`, `return`
- Identifiants, nombres entiers, caractères littéraux
- Opérateurs : arithmétiques (`+`,`-`,`*`,`/`,`%`), relationnels (`<`,`>`,`<=`,`>=`,`==`,`!=`), booléens (`&&`,`||`), accès membre (`.`)
- Commentaires `//` et `/* */`
- Gestion des caractères mal formés (multi-char entre quotes → erreur avec numéro de ligne)

**Manque :** le lexeur ne retourne pas de code de retour `1` en cas d'erreur lexicale (il imprime sur stderr et fait `exit(1)` directement).

### 2. Analyse Syntaxique (Bison) — `tpcas.y`
La grammaire TPC complète est implémentée, incluant :
- Déclarations globales de variables (simples et struct)
- Définitions de structures (`struct Nom { ... }`)
- Déclarations de fonctions avec paramètres, variables locales, corps
- Expressions : arithmétiques, booléennes, comparaisons, unaires, accès membre (`.`), appels de fonctions
- Instructions : affectation (`=`), `if`/`else`, `while`, `return`
- L'extension structs est bien intégrée

**Conflits :** 1 conflit shift/reduce déclaré (`%expect 1`), résolu.

### 3. Construction de l'AST — `tree.c` / `tree.h`
- Nœuds typés avec labels (`NODE_Prog`, `NODE_DeclVars`, `NODE_DeclFonct`, `NODE_ASSIGN`, `NODE_ADDSUB`, `NODE_DOT`, etc.)
- Chaque nœud stocke : label, texte, numéro de ligne, premier enfant, frère suivant
- Option `-t` / `--tree` : affichage de l'AST et génération d'un fichier `.dot` (Graphviz)
- Option `-h` / `--help` disponible

### 4. Table des Symboles Globale — `compiler.c`

**Structures de données :**
- `struct variable_info` : nom, type (`INT`/`CHAR`/`STRUCTURE`), adresse/offset, lien vers définition de struct, lien vers conteneur
- `struct definition_info` : nom, kind (`D_STRUCT`/`D_FUNC`), type de retour, liste paramètres, liste locaux, corps AST, taille totale
- `struct table_symbole` : union taguée (`SYMBOL_VAR` / `SYMBOL_DEF` / `SYMBOL_EMPTY`)

**Ce qui est implémenté :**
- Pré-remplissage avec les 4 fonctions built-in : `getchar`, `putchar`, `getint`, `putint`
- Remplissage des structs : champs avec offsets calculés, taille totale
- Remplissage des fonctions : paramètres, variables locales, offsets
- Remplissage des variables globales : offset global calculé
- Détection des doublons (variables, paramètres, fonctions)
- Lookup : `find_variable()`, `find_in_table_symbole()`
- Affichage formaté de la table (`-s` / `--symtabs`)

### 5. Vérification Sémantique (TDC6) — `compiler.c`

**Implémenté :**
- Vérification que toutes les variables/paramètres utilisés dans les instructions sont déclarés (`check_all_declarations`)
- Vérification que les fonctions appelées sont déclarées
- Calcul du type des expressions (`get_expr_type`) : variables, constantes, appels, accès `.`, opérations
- Warning si on affecte un `int` à un `char` (`NODE_ASSIGN`)
- Warning si une fonction `void` est utilisée comme expression
- Détection des champs de struct invalides via accès `.`

## ⚠️ Ce qui est partiellement implémenté

### 6. Génération de Code NASM — `instruction.c` + `compiler.c`

Le début de la génération de code est présent mais **très incomplet et incorrect** :

**Ce qui existe :**
- Ouverture du fichier `_anonymous.asm` en écriture (via `fill_global_symbol_table` qui reçoit un `FILE *fp`)
- Écriture de `section .bss` pour les variables globales (`resb`, `resd`)
- Pour la fonction `main` : écriture d'un prologue (`section .data`, `section .text`, `global main`, `extern printf`, `main:`)
- `calculate_expr()` : génération partielle d'expressions arithmétiques (add, sub, imul, idiv, or, and, cmp/set)
- `read_instructions()` : parcours des instructions du corps d'une fonction, gestion partielle de `NODE_ASSIGN` et `NODE_RETURN`

**Problèmes majeurs :**
- Le prologue généré utilise `global main` + `extern printf` → **non conforme** au sujet qui demande `global _start` + syscall Linux (`mov rax, 60 / mov rdi, 0 / syscall`) pour un exécutable autonome
- Le fichier `_anonymous.asm` actuel contient un `section .bss` vide suivi du code `main` avec un appel `printf` hard-codé → **ne s'assemble pas correctement** en ELF64 autonome
- `calculate_expr()` a des bugs : accès à `exprNode->firstChild->nextSibling->text` sans vérification de null ; confusion entre opérandes gauche et droite
- Pour `NODE_ASSIGN`, la génération ne fonctionne que pour les affectations de variables globales et uniquement dans le cas d'une soustraction simple
- Pas de gestion des variables locales (accès via `[rbp - offset]`)
- Pas de prologue/épilogue de fonction (`push rbp / mov rbp, rsp / sub rsp, N / ... / leave / ret`)
- Pas de génération pour `if/else`, `while`
- Pas d'appels de fonctions générés
- Pas de `putchar`, `putint`, `getchar`, `getint` écrits en NASM
